# Snapshot Health Checks

日期：2026-09-07

## 目的

這份檢查用來抓出資料層的靜默失敗：欄位存在、但覆蓋率過低、分布異常、或單位/期間定義與 UI 使用方式不一致時，不會直接終止整個掃描流程，但會留下明確 warning。

## 檢查項目

### 1. 覆蓋率守門

檢查以下欄位是否低於閾值：

- `pe_ratio`
- `roe`
- `dividend_yield`
- `market_cap`

如果非零值覆蓋率低於 80%，記錄警示：

- `field coverage is low (x%); expected > 80%.`

這可直接抓出 `market_cap` 0% 的異常情況，避免整個候選集被錯誤清空。

### 2. 合理範圍守門與警告聚合 (Warning Aggregation)

檢查常見異常值，例如：

- `pe_ratio > 200`
- `roe < -100` 或 `roe > 200`
- `dividend_yield > 20` 或 `< -20`
- `market_cap <= 0`

**警告聚合機制**：若違規標的超過 3 檔（如市值為 0 的全市場 1832 檔），系統會自動聚合成單一摘要警告（列出受影響總檔數與前 3 檔範例），避免數千則警告淹沒日誌（確保 warning 總數維持在 50 則以下）。

### 3. 已知標的基準檢查（Ground Truth Benchmarks）

針對核心代表權值股設定預期合理的真實區間，專門偵測「數值落在正常數值範圍內、但期間/定義錯置」的靜默問題（例如：單季 ROE 5.8% 表面看似合理，但對台積電年化 ROE 而言嚴重失真）：

- **2330 台積電**：年化 ROE 預期 `[15.0%, 45.0%]`（若 <15% 代表誤存單季值）、PE `[10.0, 50.0]`
- **2412 中華電**：殖利率預期 `[2.5%, 7.0%]`、年化 ROE `[6.0%, 15.0%]`
- **2317 鴻海**：年化 ROE `[7.0%, 20.0%]`、PE `[5.0, 30.0]`
- **2454 聯發科**：年化 ROE `[10.0%, 50.0%]`

若基準標的數值偏離區間，觸發 `[基準檢測異常]` 警示。

## 議題實例

已知案例：

- `market_cap` 0% 覆蓋率（由覆蓋率守門＋聚合異常警告捕捉）
- `dividend_yield` 出現 496.94% 異常值（由極端值範圍守門捕捉）
- `roe` 單季值 5.81% 誤當年化值（由台積電已知標的基準守門捕捉）

這些問題都會在健康檢查中被標記出來，並且不會因為警示而停掉整個流程。

## 如何新增檢查

新增檢查時請保持以下規則：

1. 只檢查資料層可驗證的事實，不假設未確認的商業規則。
2. 先做 warning，不做 hard fail，避免一次資料小問題讓整個排程停掉。
3. 重複性大量違規應聚合輸出，總 warning 數保持在可讀範圍（< 50 則）。
4. 若需要修正欄位語意，請同步更新 UI/Filter/資料來源的共識，不能只修一側。
